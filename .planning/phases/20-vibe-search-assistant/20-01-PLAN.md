  id: string;

2. Create `src/lib/filter-presets.ts` with:

a) Import MapFilters from `@/types/map` and re-export DEFAULT_FILTERS from `@/hooks/use-map-filters` (or define it locally to avoid circular deps -- see note below).

b) Define FILTER_PRESETS array with these exact mappings (from RESEARCH.md dimension analysis):

- **work_study**: `{ wifiMin: 4, quietnessMin: 4, comfortMin: 4, hasPowerOutlets: true, isLaptopFriendly: true }` with icon "Laptop", labelKey "map.presets.workStudy"
- **aesthetic_date**: `{ lightingMin: 5, drinksMin: 4, comfortMin: 4 }` with icon "Heart", labelKey "map.presets.aestheticDate"
- **quick_stop**: `{ priceValueMin: 4, foodMin: 3 }` with icon "Zap", labelKey "map.presets.quickStop"

NOTE on dimension mappings from research:
- "aesthetic" maps to `lightingMin` (no aesthetic filter exists)
- "max_noise: 2" maps to `quietnessMin: 4` (inverse scale)
- "service" dimension omitted (no filter exists)
- "power_outlets: true" maps to `hasPowerOutlets: true`
- `isLaptopFriendly: true` added to work_study (natural fit)

c) Create the `matchesPreset` function that:
- Takes `currentFilters: MapFilters` and `presetFilters: Partial<MapFilters>`
- For each key in presetFilters, checks if currentFilters has the same value
- For arrays: compares length and element equality
- For primitives (number, boolean): strict equality
- ALSO checks that no extra filters are active beyond the preset (prevents partial match false positives)
- "Extra filter active" means: number > 0 (and not null), boolean === true, array.length > 0
- Skip `showFavoritesOnly` from the extra-filter check (it's a UI toggle, not a vibe filter)
- Returns boolean

d) Export a helper `getMatchedPreset(filters: MapFilters): FilterPreset | null` that iterates FILTER_PRESETS and returns the first match, or null.

IMPORTANT: Do NOT import from `use-map-filters.ts` in this file to avoid circular dependencies. Instead, define the DEFAULT_FILTERS reference values inline in the matching logic (check against null/0/false/empty-array defaults).
