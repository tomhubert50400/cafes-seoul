## Design Decisions

**From 07-CONTEXT.md:**
- Single-page form (NOT multi-step wizard)
- Fields ordered: most important → least important
- Validation triggers on submit, not inline
- Duplicate detection shown in modal dialog
- User can proceed despite warning or cancel
- Rate limiting blocks with clear explanation (not just warning)

**Form Fields (in order):**
1. Cafe Name (translated - required)
2. Address (translated - required)
3. Phone number (optional)
4. Location (lat/lng - optional, can be auto-filled from address)

**UI Patterns to Follow:**
- Use existing form components from src/components/ui/
- react-hook-form + Zod for validation (existing pattern)
- Sonner toast for success/error notifications
- i18n via useI18n() hook (5 languages: ko, en, fr, zh, vi)

  <action>
Create Zod validation schemas for the cafe submission form.

**Create src/lib/validations/submission.ts:**

1. **translatedTextSchema:**
   - Object with at least one language having non-empty string
   - Require 'en' OR 'ko' to have value (at least one)
   - Other languages optional: fr, zh, vi
   - Schema shape: { en?: string, ko?: string, fr?: string, zh?: string, vi?: string }
   - Validation: At least one of en/ko must have min 2 chars

2. **submissionSchema:**
   - name: translatedTextSchema
   - address: translatedTextSchema
   - phone: z.string().optional().refine(phone validation if provided)
     - Phone regex for Korean format: /^\d{2,4}-?\d{3,4}-?\d{4}$/ or international
   - latitude: z.number().min(-90).max(90).optional()
   - longitude: z.number().min(-180).max(180).optional()

3. **Export types:**
   - export type SubmissionFormData = z.infer<typeof submissionSchema>

**NOTES:**
- Match existing validation patterns from codebase
- Keep validation messages suitable for i18n (use generic messages)
- Phone validation should be lenient (various formats)
- Coordinates optional but validated if provided
- Use .refine() for custom logic (like at least one translation)

**Reference pattern from codebase:**
```typescript

```

**Form layout:**
- Container: max-w-2xl mx-auto, card-like styling
- Section headers with step numbers (visual only, not multi-step)
- Required field indicator (*)

**Fields (in order):**

1. **Cafe Name Section:**
   - Label: "Cafe Name" + required indicator
   - Tabs or stacked inputs for each language
   - At minimum: English and Korean input fields
   - Optional: French, Chinese, Vietnamese
   - Help text: "Enter the cafe name in at least one language"

2. **Address Section:**
   - Same pattern as name (multi-language inputs)
   - Label: "Address"
   - Help text: "Full street address"

3. **Phone Section:**
   - Single text input
   - Label: "Phone Number (Optional)"
   - Placeholder: "02-1234-5678"
   - Help text: "Contact number if available"

4. **Location Section (Optional):**
   - Collapsible or secondary section
   - Two number inputs: Latitude, Longitude
   - Help text: "Precise coordinates if known"
   - Future: Could add map picker button

**Form behavior:**
- Use react-hook-form with zodResolver
- Validation mode: onSubmit (not onChange per CONTEXT.md)
- Submit button: "Submit Cafe" (create) or "Update Submission" (edit)
- Loading state: Button shows spinner, form disabled
- Error display: Toast notification for API errors, inline for validation

**Duplicate detection flow:**
1. User clicks Submit
2. Form validates
3. Call onCheckDuplicates with name + address
4. If duplicates found: show DuplicateDetectionModal
5. If no duplicates or user confirms: proceed with onSubmit

**Rate limit handling:**
- If rateLimit.remaining === 0: show RateLimitBlock instead of form
- Otherwise show: "You have X submissions remaining today"
