<task type="auto">
  <name>Create photos API endpoint with vote status</name>
  <files>src/app/api/photos/route.ts</files>
  <action>
Create API route for fetching photos with current user's vote status:

1. Route: GET /api/photos?cafeId={id}&offset={n}&limit={6}

2. Query parameters:
   - cafeId: string (required)
   - offset: number (default 0)
   - limit: number (default 6, max 20)

3. Logic:
   a. Get current user (if authenticated)
   b. Build query:
      - SELECT photos.*, COUNT(photo_votes.id) as upvote_count
      - LEFT JOIN photo_votes ON photos.id = photo_votes.photo_id
      - WHERE photos.cafe_id = cafeId
      - AND (
        photos.status = 'approved'
        OR (photos.user_id = currentUserId AND photos.status IN ('pending', 'approved'))
      )
      - GROUP BY photos.id
      - ORDER BY upvote_count DESC, photos.created_at DESC
      - LIMIT limit OFFSET offset

4. Check user's votes:
   - For authenticated users: get list of photo_ids they voted for
   - Add hasVoted: boolean to each photo in response

5. Response format:
   ```json
   {
     "photos": [
       {
         "id": "uuid",
         "storage_path": "path",
         "status": "approved",
         "upvote_count": 5,
         "hasVoted": true,
         "created_at": "timestamp",
         "isOwnPhoto": false
       }
     ],
     "total": 12,
     "hasMore": true
   }
   ```

6. Error handling:
   - Return 400 if cafeId missing
   - Return 500 for database errors
   - Standard error format: { error: string }

7. Storage URL generation:
   - Return storage_path, not full URL
   - Client constructs URL from storage_path
   - Use getStorageUrl helper from utils

8. Security:
   - Only show pending photos to their uploader
   - Never reveal uploader identity (no user_id in response unless isOwnPhoto)
  </action>
  <verify>API returns photos with correct vote counts and visibility rules</verify>
  <done>Photos API with vote status and proper filtering</done>
</task>
