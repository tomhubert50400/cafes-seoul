<task type="auto">
  <name>Task 1: Create password reset Server Actions</name>
  <files>
    src/lib/actions/password.ts
  </files>
  <action>
Create src/lib/actions/password.ts with two Server Actions:

1. requestPasswordReset(email: string):
   - Validate email with Zod
   - Call supabase.auth.resetPasswordForEmail(email, { redirectTo })
   - redirectTo: `${process.env.NEXT_PUBLIC_SITE_URL}/reset-password`
   - ALWAYS return { success: true } to prevent email enumeration (per RESEARCH.md)
   - Do NOT reveal if email exists in database

2. updatePassword(newPassword: string):
   - Import and call initZxcvbn() at module level for server-side validation
   - Validate with passwordSchema (min 8 chars, zxcvbn score >= 2)
   - Call supabase.auth.updateUser({ password: newPassword })
   - On success: Call supabase.auth.signOut({ scope: 'global' }) - terminates ALL sessions
   - Return { success: true } or { error: { password: [message] } }

Note: Supabase automatically handles the password reset token exchange when the user lands on the reset page. The session is set via the PKCE code in the URL.

Error handling:
- For resetPasswordForEmail: silently succeed even if email doesn't exist
- For updateUser: return specific error message if password update fails
  </action>

    - Both functions exported and typed correctly
  </verify>
  <done>
    - requestPasswordReset sends reset email without revealing if email exists
    - updatePassword validates strength server-side and signs out globally
  </done>
